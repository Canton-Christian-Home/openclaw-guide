Enforce a Rigid Markdown Workspace Structure

  

  
OpenClaw has no hidden database for agent rules — it reads raw Markdown files from disk every time a session boots. Use the generator above to fill in ~/.openclaw/workspace with these strictly defined files:

  

    

      
Operating Instructions

      AGENTS.md
      
Hard rules for behavior and formatting (e.g., “Always output data in Markdown tables, never lists”) — these stick even during sub-agent loops.

    

    

      
Personality & Constraints

      SOUL.md
      
Tone, personality bounds, and rigid constraints (e.g., “Never reply directly to an unknown contact unless explicitly approved”).

    

    

      
User Context

      USER.md
      
Who you are, your preferences, and your environmental boundaries.

    

    

      
Focus Lock

      ACTIVE-TASK.md
      
The agent writes its current objective here so deep multi-turn chat history doesn't derail it.

Implement “Recursive Improvement” to Build Skills

  

  
Turn successful executions into predictable Standard Operating Procedures instead of vague chat commands.

  
    
    
  1. Instruct precisely. Provide a highly specific, step-by-step instruction for the task over chat.
    2. 
    
  2. Let it execute once. Run the task end-to-end until the agent completes it successfully.
    3. 
    
  3. Freeze it. Command the agent: Document the exact steps you just took and convert this into an OpenClaw skill.
    4. 
    
  4. Reuse forever. The action is now a deterministic, reusable skill package the agent can replicate perfectly.
    5.

Deploy a Multi-Agent “Chief of Staff” Hierarchy

  

  
A single agent with every tool enabled juggles too many variables and produces inconsistent output. Use an orchestrator architecture:

  

    
RoleModel tierResponsibility

    
Orchestrator (“Chief of Staff”)Heavy frontier model (Claude Sonnet / Opus class)Reasoning, planning, and task routing.

    
Coding sub-agentFast, cost-effective modelIsolated code generation and execution.

    
Research sub-agentMid-tier model with web accessWeb lookups and information gathering only.

  

  
Isolate tool paths: filter per-agent allowlists. If a sub-agent only needs to read emails, strip its file-writing and shell capabilities entirely.






  

    
4

    
Activate the Self-Improvement and Learning Hooks

  

  
Install the self-improving agent skill from Clawhub, then enable the hook in ~/.openclaw/openclaw.json. The generator above produces this file with your setting baked in:

  
"hooks": {
  "self-improvement": true
}

  
This creates a .learning/ directory containing learning.md and errors.md. When you correct the agent mid-session, it logs the error to disk — preventing the behavioral regression common in stateless LLM apps.






  

    
5

    
Control Inputs via Structured Channels and Crons

  

  
OpenClaw's “proactivity” comes from systematic loops. Configure rigid gates in the gateway control plane.

  

    

      
🔗 Standardize Message Handoffs

      
Use structured JSON schemas for data passed between sub-agents. Unstructured text degrades as it hops between agents — schemas keep payloads lossless.

    

    

      
⏱ Stagger Cron Schedules

      
Stagger cron triggers so task A completes fully before task B starts, preventing token rate-limiting failures.
